# 将视觉图表转化为结构化代码

**适用场景**：任务是将草图、流程图、架构图或白板内容转换为 Mermaid、Graphviz、JSON 或其他结构化表示形式。目标是保持语义和拓扑结构的准确性，而非追求与源渲染器像素级一致。

## 步骤

1. 对整张图片执行一次 `glance` 扫描，以识别图表类型、阅读方向、主要分组和视觉惯例。
2. 使用 `detect` 进行初始节点和标签清单的提取。对于密集区域，使用 `detect --region` 进行细化。
3. 使用 OCR 识别标签。保留可见的拼写、标点和缩写原样；对于无法辨认的内容，请标注 `[unreadable]`，切勿猜测。
4. 使用 `ground` 和针对性的 `glance --region` 调用来定位模糊的箭头、连接线、图例和分组边界。
5. 在编写输出之前，先构建一份明确的中间清单：节点、标签、分组、边、方向和边标签。
6. 根据该清单生成 Mermaid、Graphviz 或所请求的结构。

## 验证结构，而非像素

渲染结果后，再次进行清单核对，并将以下事实与参考进行对比：

- 节点数量和标签集合
- 组成员关系和嵌套结构
- 边列表及其方向
- 边标签和分支条件
- 起点/终点或输入/输出角色

像素差异是预期内的，因为目标渲染器会自行决定字体、间距和路径。即使两张图片整体看起来相似，缺失节点或箭头方向反转也属于失败；而结构正确时，不同的曲线或间距并不算失败。

## 边界

- 除非用户要求编辑性清理，否则不要整理标签、展开缩写或静默修正措辞。
- 不要仅凭邻近关系推断边的存在。如果边的端点或方向不明确，请放大连接处，并明确标记未解决的事实。
- 如果用户需要的是视觉 SVG 副本而非结构化代码，请遵循 `restore-graphic.md` 的指引。
