# 通过截图操作 GUI

**使用时机**：任务需要在实时屏幕上进行操作——点击、输入、滚动——并以截图作为指导：驱动应用、自动化工作流、复现 bug 步骤。视觉层回答“在哪里”和“处于什么状态”；操作本身则通过任务已有的自动化通道执行。

工具语法位于 `SKILL.md` 中。本文件是操作顺序及通过/失败测试的说明。

## 步骤

**1. 在首次点击前，先校准一次坐标。**

截图像素与指针坐标通常是不同的空间：在 HiDPI 显示器上，截图的尺寸是点击 API 所需逻辑点数的 2-3 倍。将截图的像素宽度与屏幕的逻辑宽度进行比较，并用该比例除以每个框的坐标。跳过此步骤会导致每次点击都偏离原点一半或一倍的距离——这种系统性错误看起来像是定位不准。

**2. 优先使用 UI 树；视觉定位作为备选。**

如果环境暴露了 UI 树（Android 的 `uiautomator dump`、桌面辅助功能树、浏览器 DOM），请从其中读取坐标和状态——它精确、快速，并且携带像素无法提供的语义属性（启用、选中、可聚焦）。仅在以下情况使用 `ground`：

- 没有可用的 UI 树（游戏、自定义渲染的画布、远程桌面），
- 目标元素不在 UI 树中（画布绘制的覆盖层、非标准控件），或
- 需要验证 UI 树未暴露的视觉状态（颜色、图标外观）。

使用 `ground` 时：取中心点，而非角落——ground 框的边缘并非像素级精确。对于微小目标（复选框、关闭按钮），采用从粗到细的策略：先定位包含该元素的区块，然后在其内部使用 `ground --region`。

对于在交互中位置保持不变的元素（工具栏按钮、侧边栏链接、固定面板），只需定位一次并记录坐标表——包含 id/标签及中心坐标。后续点击直接引用表中的条目，无需每次重新运行 ground。当布局发生变化（窗口大小调整、导航到不同页面、滚动）时，使该表失效。

**3. 每次操作对应一张截图——操作、重新截图、验证，然后继续。**

每个操作都会使当前截图失效：菜单打开、焦点移动、内容加载；滚动会同时使所有框的坐标失效。在一张过时的截图上连续点击，就可能点击到原本对话框所在的位置。

**4. 将验证视为对预期状态的问题。**

`glance <after.png> -q "设置对话框是否已打开？"`——询问操作应产生的状态，而非一般性描述。如果答案是否定的或出乎意料，请停止并重新盘点（`detect`），而不是在假定的屏幕上继续操作。当变化很小时（开关切换、单个徽标），先进行差异比较：`pixel_diff before.png after.png` 可找到变化的区域，`glance --region` 可读取该区域。

**5. 输入后，回读字段内容。**

焦点丢失会静默吞掉按键。`glance --region <字段框> --ocr` 可确认文本在提交前确实已输入。

## 验证

步骤 3-4 中的循环*就是*验证：在新鲜截图回答预期状态问题之前，任何操作都不算完成。对于多步骤流程，最终截图必须显示任务定义的结束状态——确认页面、已保存指示器。操作列表完成并不算证据；像素才是。

## 边界

- 加载是异步的：在触发加载的操作后，进行轮询——重复截图，直到连续两张截图不再有差异（`pixel_diff` 接近 0）——而不是依赖固定的等待时间。
- 不可逆操作（发送、删除、支付）遵循调用代理自身的确认策略。视觉层只报告屏幕上的内容；它绝不做出该决定。
- 任务未预料到的屏幕——错误对话框、权限提示、登录墙——应停止并上报，而不是点击跳过。点击未知对话框是自动化造成损害的方式。
